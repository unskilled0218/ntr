## scope

Disable gesture-driven page zoom in the Tauri client: touchscreen pinch in/out, double-tap page zoom where supported, and desktop trackpad pinch delivered as browser zoom events. Apply the behavior throughout the app, including the note editor, task list, settings, and dialogs. Preserve normal scrolling, one-finger view switching, text editing/selection, link gestures, and existing keyboard behavior. Do not modify the server, synchronization, storage, or task semantics. This planning task changes only this document.

## Implementation Plan

### Summary

`app/index.html` currently has a normal viewport declaration with `viewport-fit=cover` and no zoom policy. `app/src/style.css` uses internal scroll regions inside a fixed-height page, and `app/src/App.tsx` implements one-finger horizontal view switching. `app/src/components/useLinkGestures.ts` owns Ctrl/Cmd-click and touch long-press behavior. The tracked Android `MainActivity.kt` already has an `onWebViewCreate` hook for keyboard insets. Use touch-action and native WebView settings for touch zoom, with a small cancellable-event helper for desktop zoom gestures; do not intercept general touch or editing events.

### 1. Prevent native touch zoom without disabling panning

- Add a documented `touch-action: pan-x pan-y` policy to the existing universal rule in `app/src/style.css`. This explicitly permits horizontal and vertical panning but not pinch zoom or double-tap page zoom. Apply it to actual event targets and internal scroll containers, not only `body`: touch-action is not inherited, and ancestor evaluation can stop at the nearest scrolling element.
- Ensure dialogs, picker lists, the contenteditable note, and input controls inherit the same effective policy through selector coverage. Check for conflicting overrides before adding exceptions. Do not use `touch-action: none`, `user-select: none`, global double-click cancellation, or blanket touchstart/touchmove prevention.
- In `app/src-tauri/gen/android/app/src/main/java/com/my/ntr/MainActivity.kt`, configure the WebView in the existing `onWebViewCreate` callback: call `webView.settings.setSupportZoom(false)` and set `builtInZoomControls` and `displayZoomControls` to false. Preserve the current edge-to-edge setup, keyboard-inset listener, and unconsumed system-bar insets exactly.
- Keep the viewport's existing scale, device width, and `viewport-fit=cover`. Do not rely on `user-scalable=no` or maximum-scale metadata as the sole solution; some engines ignore these restrictions, and they would obscure the intended gesture-only scope. Do not continuously reset zoom or apply CSS transforms to undo gestures after they happen.

### 2. Cancel desktop zoom gesture events

- Add a small frontend module such as `app/src/lib/zoomGestures.ts` exporting an installer that takes a Document and returns an idempotent cleanup function. It should know nothing about Tauri, transport state, note contents, or React state.
- Register a capturing, explicitly non-passive `wheel` listener. Prevent the default only when `ctrlKey` is true and the event is cancelable, covering trackpad pinch represented as Ctrl+wheel. Leave ordinary wheel events, Shift+wheel, and ordinary two-finger scrolling untouched. Do not broadly cancel Meta+wheel without evidence that the supported host uses it for page zoom.
- Register capturing, non-passive `gesturestart` and `gesturechange` listeners for WebKit-style page zoom gestures. Use the normal Event interface and cancellation rather than introducing an unsupported global GestureEvent declaration. Engines that do not emit these events need no special branch.
- Install the helper from an app-level effect in `app/src/App.tsx` and return its cleanup. The guard must not depend on pane readiness, the selected view, settings state, or connection state, so zoom remains disabled while loading and while dialogs are open. Keep registration/removal options consistent and preserve StrictMode setup/cleanup behavior without duplicate active listeners.
- Do not intercept keydown, click, pointer, input, composition, clipboard, or general touch events. Keyboard-only zoom commands are outside this task; leave their existing host behavior unchanged. Ctrl+wheel is intentionally suppressed even when generated by a physical mouse, because the standard wheel event does not reliably distinguish it from trackpad pinch.

### 3. Protect existing interactions with regression tests

- Add focused helper tests, for example `app/src/lib/zoomGestures.test.ts`, that dispatch cancelable Ctrl+wheel events with positive and negative deltas and assert default prevention. Verify ordinary wheel, Shift+wheel, and keyboard/click events remain uncanceled. Include wheel targets inside a scrolling element, an input/editor, and a dialog to exercise document-level capture rather than only dispatching on Document.
- Test WebKit-style gesturestart/gesturechange cancellation, noncancelable events without errors, cleanup, repeated cleanup, and reinstall. Assert dispatch after cleanup is not prevented by this helper; do not merely assert addEventListener call counts.
- Extend `app/src/App.test.tsx` or add a focused app interaction test for StrictMode mount/unmount and for the guard remaining active across view switches and settings opening/closing. Verify unmount removes the app's guard rather than leaking document listeners into later tests.
- Cover existing one-finger horizontal navigation in mobile layout, vertical movement that must not switch views, and a two-finger sequence that must not become a navigation swipe. Mock only the mobile computed-style seam where jsdom cannot evaluate responsive CSS. Keep navigation changes limited to a demonstrated regression caused by this task.
- Retain the existing note IME, caret/selection, undo, paste, link long-press, Ctrl/Cmd-click, picker, and nested dialog suites. Use those regressions plus targeted tests rather than creating a new input framework. Keep fixtures isolated and restore global listeners and style mocks after every test.
- jsdom cannot prove native page-scale behavior or CSS gesture arbitration. A stylesheet/native-settings contract check can protect configuration, but must not be reported as evidence that physical pinch or double-tap zoom is disabled on a device.

### 4. Verify native behavior and update documentation

- Run `npm test` and `npm run build` in `app/`. Run `cargo test -j 1` and `cargo clippy --all-targets -j 1` in `app/src-tauri/` to guard native startup compatibility. No new package should be needed; report missing build prerequisites instead of installing system packages.
- Build the Android debug app with the project's existing Android workflow when its SDK/toolchain is available, because desktop Cargo checks do not compile MainActivity. Preserve existing generated-project conventions rather than regenerating the Android project. Record unavailable toolchains or device checks explicitly.
- On Android, verify pinch in and out and double-tap in both panes, a scrollable picker, and an open settings dialog. Observe unchanged page scale; then verify scrolling, text selection, keyboard appearance/insets, IME composition, long-press link confirmation, and one-finger navigation still work.
- On supported desktop WebViews with available hardware, verify trackpad pinch is blocked in both directions, ordinary two-finger scroll still works, and Ctrl/Cmd-click links, selection, wheel scrolling, and keyboard shortcuts retain their prior behavior. Check Linux/WebKitGTK and macOS/WebKit or Windows/WebView2 when available; report untested platforms rather than claiming universal validation from synthetic events.
- Update `app/docs/features.md` with the gesture policy and its distinction from ordinary scrolling and OS accessibility magnification. Add a concise relevant note to `app/README.md`; use a dedicated input/gesture document only if platform-specific details warrant it. Preserve Markdown tables of contents. Record implementation results in this task's `4-implemented.md` during implementation.
- Follow the existing patch-version convention during implementation: advance client `0.15.24` to `0.15.25` consistently across npm, Cargo, lockfiles, and Tauri configuration if no intervening release changes the base version. Commit app changes in the submodule and update the parent gitlink as part of the task workflow; do not modify unrelated `todo.md` work.

## Acceptance Criteria

- Touchscreen pinch in/out and double-tap page zoom do not change the app's page scale on validated supported devices, including inside internal scrolling regions and dialogs.
- Ctrl+wheel zoom events and WebKit gesturestart/gesturechange are canceled when cancelable. Normal wheel and two-finger scrolling remain available.
- Zoom suppression is active independently of pane loading, connection settings, selected view, or dialog state, and does not leak duplicate listeners under StrictMode or after unmount.
- One-finger horizontal navigation, vertical scrolling, text editing/selection, IME, undo/paste, long-press links, Ctrl/Cmd-click links, and modal dismissal remain functional. A multi-touch gesture does not switch panes.
- The Android WebView disables native zoom controls/support without changing edge-to-edge or keyboard-inset handling. Existing keyboard behavior and OS-level accessibility magnification are not intentionally changed.
- Automated tests/build pass. Physical gesture and Android compilation results are recorded separately, including any unavailable environment or untested platform.

## Risks And Decisions

- Desktop trackpad pinch often shares Ctrl+wheel with physical mouse zoom; rejecting both is the deliberate tradeoff. Do not infer gesture origin from unreliable heuristics.
- Touch-action must cover nested scroll containers and top-layer dialogs. A body-only rule or `manipulation` is insufficient: manipulation still permits pinch zoom. Avoid disabling all touch input to compensate.
- Native zoom behavior differs across Android Chromium, WebKitGTK, WebKit, and WebView2. Keep each suppression mechanism narrow and verify native behavior; add another native hook only for a reproduced supported-host gap, not speculatively.
- Disabling page zoom gestures reduces one way to enlarge content. Preserve text selection, existing keyboard behavior, and system accessibility magnification. OS magnifiers are outside application page zoom and are not a validation failure.
- This task does not repair unrelated existing transport/reconnect review findings or expand the server WebUI's interaction policy. Keep those concerns out of the zoom implementation.
