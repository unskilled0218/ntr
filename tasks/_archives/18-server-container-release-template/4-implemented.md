## Changes

Prepared server version `0.2.5` using container-release-template `0.5.0`, pinned at `3c73528231ac1cbdd43600a5ca723390db804bac`. Added the Bash entry point/shared guards, standard-library Python helper, strict server-specific `release.json`, canonical `VERSION`, checked Cargo/README mirrors, and committed project release notes. Removed the old Python publisher after mapping its applicable behavior to the adapted tests in `server/docs/release-verification.md`.

The workflow requires clean, already-pushed server `main`, complete bounded inventories, private external token-file credentials, and an existing two-platform builder. It snapshots committed source, verifies immutable multi-platform image/configuration identity, publishes an exact annotated tag, promotes by digest to `latest`, creates a notes-only release, and verifies scoped package association. Conflicts and ambiguous partial states refuse without rollback, force pushes, reassignment, or blind write replay. Stable Gitea `1.25.x` remains required for new package links; correct existing links can verify without that write gate.

Local deviations close the reference's known warnings: N1 makes confirmed promotion one-way, refusing predecessor/missing/foreign aliases before subsequent writes; N2 captures the selected Buildx path/version/hash, references only that executable through a private run-owned plugin symlink, and verifies identity under isolated authentication. Additional deviations enforce Rust/README version mirrors, reject deprecated `FORGEJO_*` publishing overrides, normalize equivalent default HTTPS ports in same-origin registry authentication, and enumerate all effective Git URLs to require exactly one destination per direction. The latter prevents an unchecked secondary push URL from receiving a release tag. No upstream fix is claimed.

The real Rust/Bookworm image, locked binary build, UID/GID `1000:1000`, port, persistent paths, narrow Docker context, and runtime behavior remain unchanged. Buildx supplies verified OCI labels instead of empty Dockerfile build arguments. Compose now selects the supported mutable `latest` alias; documentation recommends verified immutable digests. Automatic builder creation, versioned container aliases, archive attachments, and raw streaming build logs are deliberately retired, without deleting historical artifacts. Dedicated configuration, publication/recovery, and verification documents explain migration and limitations; README, Compose, and development documentation link them.

## Limits and remaining checks

`cargo test --locked`, `cargo clippy --all-targets --locked`, and `cargo fmt --check` each failed with exit `127`: `cargo: command not found`. Both Cargo and rustc are absent, including the usual user/local Cargo bin directories. Install the Rust toolchain with Cargo, rustfmt, and Clippy to run these checks; no toolchain or privileged host setup was installed during this task.

No actual image build or runtime smoke test ran because the available Docker daemon was not confirmed non-production. AMD64/ARM64 builds, runnable-architecture non-root/API/persistence smoke checks, and native application verification remain outstanding. Fake-port tests do not certify live registry/TLS behavior, account permissions, deployed API compatibility, package-link refusal semantics, Packages-tab rendering, or distributed writer exclusion. Version `0.2.5` is prepared, not published; `latest` may not exist until a separately approved publication. These limits prevent claiming live publication readiness.
